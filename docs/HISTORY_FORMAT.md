# 히스토리 기록 형식

[README로 돌아가기](../README.md)

Mato Blog Codex는 사용자가 어떤 명령을 입력했고 각 단계에서 무엇이 진행됐는지 사람이 읽을 수 있는 Markdown과 프로그램이 재개에 사용하는 JSON으로 기록합니다.

플러그인 버전 변경 내역은 루트의 [CHANGELOG.md](../CHANGELOG.md)를 참고하십시오. `CHANGELOG.md`와 사용자 실행 `HISTORY.md`는 서로 다른 문서입니다.

## 기록 위치

| 기록 | 위치 | 용도 |
| --- | --- | --- |
| 실행별 히스토리 | `바탕화면/YYYY-MM-DD/<실행-ID>/HISTORY.md` | 한 작업의 상세 진행 내역 |
| 실행 상태 | `바탕화면/YYYY-MM-DD/<실행-ID>/run.json` | 상태, 배정과 재개 위치를 프로그램이 판독 |
| PC 전체 히스토리 | `~/.googleblog/mato-blog-codex/HISTORY.md` | 이 PC에서 수행한 실행의 시간순 요약 |

실행 폴더는 저장소 밖 바탕화면에 있고 전체 히스토리는 사용자 홈에 있습니다. 어느 기록도 GitHub에 자동으로 포함되지 않습니다.

## 기록되는 내용

각 실행에는 한국 시간 기준으로 다음 항목을 남깁니다.

- 실행 ID, 시작·완료 시각과 총 소요 시간
- 민감정보를 제거한 사용자 명령
- 해석된 검색어, `블로그탭/통합검색`, 목표 버전 수
- 선택한 프로필 번호와 `임시저장/자동발행` 방식
- 검색 시작·완료, 수집한 글 수와 보존된 출처 URL
- 분석·원고 생성·검증 단계의 시작, 완료 또는 실패 상태
- 생성 파일 경로와 원고 제목
- 프로필별 라운드로빈 배정
- 임시저장·발행별 성공 여부와 확인 가능한 글 URL
- 중단 이유, 오류 요약, 마지막 성공 항목과 다음 재개 위치
- 실행에 사용한 플러그인 버전

다시 실행하거나 중단된 작업을 재개하면 기존 문서를 덮어쓰지 않고 새 구간을 아래에 추가합니다.

## 기록하지 않는 내용

- 네이버 비밀번호
- 쿠키, 세션 값, 인증 토큰과 API 키
- Chrome 프로필 내부 파일
- 다른 블로그 글의 전체 원문
- 요청·응답 헤더 등 인증정보가 포함될 수 있는 네트워크 원문
- 이미지 바이너리 또는 이미지 메타데이터

사용자 명령에 `password`, `passwd`, `token`, `api_key`, `cookie`, `session`, `secret`처럼 민감정보로 판단되는 값이 포함되면 값 부분을 `[민감정보 삭제]`로 바꿔 기록합니다. 민감정보는 애초에 명령에 입력하지 않는 것이 가장 안전합니다.

## 실행별 HISTORY.md 예시

```markdown
# 실행 히스토리: 20260722-113000-seoul-food

## 실행 정보

- 시작: 2026-07-22 11:30:00 KST
- 사용자 명령: 서울 맛집 블로그탭 원고 10개, 프로필 1,2,3 임시저장
- 검색어: 서울 맛집
- 검색 영역: 블로그탭
- 목표 원고: 10개
- 프로필: 1, 2, 3
- 방식: 임시저장

## 진행 기록

- 11:30:02 [검색/시작] 네이버 블로그탭 검색 시작
- 11:30:09 [검색/완료] 중복 제거 후 5개 출처 확보
- 11:35:20 [생성/완료] 원고 10개 생성
- 11:35:23 [검증/완료] 10개 통과
- 11:36:00 [업로드/확인] 배정표와 RUN_ID 내부 서명 확인
- 11:42:18 [업로드/완료] 임시저장 10개 성공

## 결과

- 상태: 완료
- 완료: 2026-07-22 11:42:18 KST
- 소요 시간: 12분 18초
```

실제 문구와 항목 순서는 플러그인 버전에 따라 조금 달라질 수 있지만, 명령·단계·결과·재개 정보를 빠뜨리지 않는 원칙은 유지합니다.

## run.json 역할

`run.json`은 사람이 직접 편집하는 문서가 아닙니다. 일반적으로 다음 상태를 포함합니다.

- 입력 값과 실행 ID
- 수집 출처와 현재 단계
- 생성된 원고 목록
- 검증 결과
- 선택 프로필과 배정
- 원고별 업로드 성공·실패·대기 상태
- 오류 요약과 재개 위치

업로드 재개는 이 파일의 성공 상태를 기준으로 이미 처리한 원고를 건너뜁니다. 파일이 손상된 경우 추측으로 발행하지 않고 중단합니다.

## 히스토리 보기

일반 사용자는 Codex에 전체 기록을 요청합니다.

```text
이 PC의 Mato Blog Codex 전체 작업 히스토리를 보여줘.
```

특정 실행 기록도 자연어로 요청합니다.

```text
방금 실행의 상세 히스토리와 재개 위치를 보여줘.
```

직접 스크립트를 확인해야 하는 개발자는 [개발자·내부 문제 해결 명령](COMMANDS.md)을 참고하십시오.

## 보관과 삭제

기록에는 비밀번호가 없더라도 검색어, 글 제목과 블로그 URL 같은 개인 정보가 포함될 수 있습니다. PC의 백업·접근 권한 정책에 맞춰 보관하십시오.

삭제하려면 먼저 정확한 실행 폴더를 확인하고 필요한 결과를 백업하십시오. 플러그인은 프로필이나 실행 기록을 자동 삭제하지 않으며, 저장소 전체나 사용자 홈을 대상으로 한 일괄 삭제 명령도 제공하지 않습니다.
