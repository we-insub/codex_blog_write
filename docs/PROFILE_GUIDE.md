# 네이버 프로필 생성·로그인·창 유지 안내

[README로 돌아가기](../README.md)

이 문서는 번호별 네이버 Chrome 프로필을 처음 만드는 과정부터 여러 개를 동시에 열어두고 업로드하는 과정까지 설명합니다.

## 프로필은 무엇을 저장하나

`프로필 N`은 `~/.googleblog/mato-blog-codex/browser_profiles/naver_N`에 저장되는 Codex 전용 Chrome 사용자 데이터 폴더입니다. 마토헬퍼 프로필과는 분리되며, 프로필을 초기화하거나 삭제하지 않는 한 같은 네이버 로그인 세션과 사이트 데이터를 계속 사용합니다.

프로필 카탈로그 `~/.googleblog/mato-blog-codex/naver_profiles.json`에는 다음 비밀이 아닌 정보만 저장합니다.

- 양의 정수 슬롯 번호
- `naver_N` 이름과 로컬 폴더 경로
- 사용자가 정한 계정 별칭
- 정규화된 블로그 URL과 글쓰기 URL
- 마지막 로그인·글쓰기 확인 상태와 시각

비밀번호, 쿠키 값과 세션 값은 카탈로그·Git·히스토리에 기록하지 않습니다.

공개 글 조사용 Codex `@Browser`, 일반 Chrome의 기본 프로필, 네이버 업로드용 `naver_N`은 서로 다른 브라우저입니다. 로그인 상태를 공유하지 않는 것이 정상입니다.

## URL 규칙

프로필 등록에는 네이버 블로그 ID 또는 기본 블로그 URL을 사용합니다.

| 입력 예시 | 저장되는 블로그 URL | 자동 생성되는 글쓰기 URL |
| --- | --- | --- |
| `intp_kr` | `https://blog.naver.com/intp_kr` | `https://blog.naver.com/intp_kr?Redirect=Write&` |
| `https://blog.naver.com/intp_kr` | `https://blog.naver.com/intp_kr` | `https://blog.naver.com/intp_kr?Redirect=Write&` |
| `https://m.blog.naver.com/intp_kr` | `https://blog.naver.com/intp_kr` | `https://blog.naver.com/intp_kr?Redirect=Write&` |

글쓰기 URL은 자동 계산되므로 별도로 입력할 필요가 없습니다. 개별 글 URL에서도 블로그 ID를 찾을 수 있지만 대상 혼동을 줄이려면 기본 블로그 URL을 권장합니다.

## 프로필 1개 생성

```text
프로필 1 생성해줘. 별칭은 intp_kr이고 블로그 URL은 https://blog.naver.com/intp_kr 이야.
```

이 요청은 다음 작업만 수행합니다.

1. 슬롯 1을 카탈로그에 등록합니다.
2. `naver_1` 폴더를 만듭니다.
3. 블로그 URL과 글쓰기 URL을 저장합니다.

프로필 생성은 Chrome을 자동으로 열지 않습니다. 이어서 다음 요청이 필요합니다.

```text
프로필 1 Chrome 창 열어두고 닫지 마.
```

프로필 생성·별칭 수정·블로그 URL 수정·플러그인 업데이트·실행 환경 재설치는 기존 `naver_N` 브라우저 데이터를 삭제하지 않습니다. 프로필 폴더가 사라진 경우에는 과거 `ready` 상태를 재사용하지 않고 다시 로그인이 필요한 상태로 표시합니다.

## 프로필 초기화

로그인 데이터를 지우고 같은 번호를 새 Chrome 프로필로 시작하려는 경우에만 명시적으로 요청합니다.

```text
프로필 2를 초기화해줘. RESET-2로 확인할게.
```

초기화는 해당 번호의 Codex 전용 브라우저 데이터만 지우며 별칭과 블로그 URL은 유지합니다. 다른 번호와 마토헬퍼 프로필에는 손대지 않습니다. 해당 Chrome 창이 열려 있거나 잠겨 있으면 미저장 글 보호를 위해 초기화를 거부하며, 프로그램이 창을 강제로 닫지 않습니다.

프로그램은 같은 프로필 폴더와 로컬 쿠키를 계속 재사용하지만 네이버가 보안 정책으로 서버 세션을 만료시키는 경우에는 정상 재로그인이 필요할 수 있습니다.

## 프로필 N개 일괄 생성

각 프로필의 번호·별칭·URL을 명확히 적습니다.

```text
네이버 프로필 3개 만들어줘.
1번: 별칭 intp_kr, URL https://blog.naver.com/intp_kr
2번: 별칭 youtube_intp, URL https://blog.naver.com/youtube_intp
3번: 별칭 travel_main, URL https://blog.naver.com/travel_main
```

프로필 번호에는 코드상 고정 최대 개수가 없습니다. 필요한 만큼 양의 정수 슬롯을 만들 수 있습니다. 동시에 여는 창 수는 PC 메모리와 업로드 대상에 맞게 제한하십시오.

이미 등록된 슬롯을 같은 생성 요청으로 덮어쓰지 않습니다. 수정은 다음처럼 요청합니다.

```text
프로필 2 별칭을 유튜브 메인으로 바꾸고 블로그 URL은 https://blog.naver.com/youtube_intp 로 유지해줘.
```

별칭·URL 수정은 기존 브라우저 로그인 계정을 자동으로 바꾸지 않습니다. 변경 뒤에는 실제 로그인 계정이 새 블로그를 소유하는지 다시 확인해야 합니다.

## 기존 프로필 발견

기존 Codex 전용 `mato-blog-codex/browser_profiles/naver_N` 로컬 프로필이 있으면 다음처럼 요청합니다.

```text
이 프로그램에서 전에 만든 네이버 프로필을 찾아서 번호, 경로, 별칭, 블로그 URL을 보여줘.
```

발견 과정은 브라우저 데이터를 복사하거나 합치지 않습니다. 기존 안전 경로를 같은 번호 슬롯에 연결합니다. 별칭과 URL이 비어 있으면 사용자가 보완합니다.

## 선택한 Chrome 창 열기

```text
프로필 1,2,3 Chrome 창을 각각 열어둬.
```

각 창은 다음 조건으로 실행됩니다.

- 해당 `naver_N` 폴더만 사용
- PC 내부 주소 `127.0.0.1`에만 연결되는 임시 DevTools 포트 사용
- 사용자가 볼 수 있는 일반 Chrome 창
- 프로필에 저장된 글쓰기 URL로 이동
- 로그인 화면으로 이동한 새 창에서는 네이버의 일반 `로그인 상태 유지` 선택을 먼저 준비
- 창을 자동 종료하지 않고 이후 확인·업로드가 재연결할 수 있게 유지

이미 연결기와 함께 열려 있으면 새 창을 중복 실행하지 않고 `already_open`으로 처리합니다.

## 로그인과 글쓰기 확인

각 창에서 해당 블로그의 소유 계정으로 직접 로그인합니다. 로그인 완료 뒤 다음처럼 요청합니다.

```text
프로필 1,2,3 로그인과 각 글쓰기 URL을 확인해줘. 창은 계속 열어둬.
```

Codex는 각 슬롯을 순서대로 확인합니다.

1. 네이버 홈에서 로그인 상태를 확인합니다.
2. 정상 로그인 상태 유지 옵션이 선택됐는지 확인합니다. 새로 연 로그인 창에서는 이 선택을 먼저 준비합니다.
3. 등록된 글쓰기 URL로 이동합니다.
4. 블로그 홈이나 네이버 섹션으로 튕기지 않는지 확인합니다.
5. 네이버가 실제로 재사용 가능한 로그인 상태를 저장했을 때만 `ready` 상태와 확인 시각을 카탈로그에 저장합니다.

창을 닫는 것만으로 이 프로필의 로그인 데이터가 삭제되지는 않습니다. 다만 네이버가 재사용 가능한 로그인 상태를 발급하지 않았거나 서버 측에서 보안 재확인을 요구하면 다시 직접 로그인해야 합니다. Codex는 쿠키를 복사하거나 만료 시각을 임의로 늘리지 않습니다.

등록 URL의 블로그 소유자가 아니면 업로드하지 않고 `owner_mismatch`로 중단합니다.

프로필 폴더 존재 여부만 확인하는 요청은 Chrome을 열지 않습니다.

```text
프로필 2 폴더만 검사해줘. 로그인 확인은 하지 마.
```

## 내 템플릿 준비

업로드에 사용할 모든 네이버 계정에 다음 Smart Editor 내 템플릿을 준비하면 가장 안정적입니다.

| 항목 | 값 |
| --- | --- |
| 템플릿 이름 | `제목을입력해주세요1:` |
| 제목 자리 | `제목을입력해주세요1` |
| 본문 시작 자리 | `본문2:` |

원고가 `본문1:` 또는 `인트로1:`을 사용한다면 템플릿에도 같은 이름의 자리를 추가합니다.

템플릿 목록에서 이름이 `제목을입력해주세요1`로 보이는 것은 네이버가 마지막 콜론을 생략해 렌더링한 경우이며 같은 템플릿으로 인식합니다.

템플릿은 네이버 계정별 데이터입니다. 프로필 1 계정에 만들었다고 프로필 2 계정에 자동 복사되지 않습니다. 업로드 전에 각 프로필에서 한 번씩 확인하십시오.

템플릿 자체가 없으면 기본 편집기의 안내 문구 자리로 폴백해 줄 단위 타이핑을 계속합니다. 선택된 템플릿에 원고가 요구하는 본문 영역 자리가 없거나 기본 편집기 자리도 찾지 못하면 `template_not_found`로 중단합니다. 원고 전체 붙여넣기나 DOM 직접 삽입은 사용하지 않습니다.

## 창을 열어둬야 하는 정확한 구간

| 시점 | 창을 닫아도 되는가 | 설명 |
| --- | --- | --- |
| 프로필 등록 직후 | 해당 없음 | 아직 창이 열리지 않음 |
| 로그인 완료 후, 작업 시작 전 | 가능하지만 비권장 | 세션은 디스크에 남지만 다음 작업 전에 다시 열어야 함 |
| 템플릿 로딩·제목 타이핑 | 닫으면 안 됨 | 대상 페이지가 사라져 입력 실패 |
| 본문·표·이미지 입력 | 닫으면 안 됨 | 진행 위치를 잃고 실패 |
| 임시저장·발행 클릭 후 확인 중 | 닫으면 안 됨 | 결과가 `uncertain`이 될 수 있음 |
| 완료 URL과 히스토리 확인 후 | 가능 | 다음 작업 때 같은 프로필을 다시 열 수 있음 |

창을 닫아도 저장된 로그인 세션이 자동 삭제되는 것은 아닙니다. 다만 현재 loopback 연결과 작업 페이지는 즉시 사라집니다.

업로드 중에는 사용자가 해당 창에서 다른 URL로 이동하거나 새 원고를 직접 입력하지 않는 것이 좋습니다. 플러그인은 열린 페이지의 편집기 상태를 기준으로 템플릿과 원고를 순차 처리합니다.

## 작성 중인 글 팝업

네이버가 `작성 중인 글이 있습니다. 이어서 작성하시겠습니까?` 팝업을 띄우면 플러그인은 `취소`를 눌러 새 원고 흐름을 시작합니다. 이 동작은 기존 임시저장 글을 삭제하는 것이 아니라 현재 이어쓰기 선택을 취소하는 것입니다.

팝업 구조가 달라 `취소` 버튼을 확실히 찾지 못하면 자동으로 `확인`을 누르지 않고 중단합니다.

## 동일 프로필 중복 실행 금지

같은 `naver_N`을 다음 두 곳에서 동시에 열지 마십시오.

- 플러그인이 연 전용 Chrome과 별도 Playwright 실행
- 플러그인이 연 전용 Chrome과 사용자가 직접 실행한 같은 `--user-data-dir`
- 동일 프로필을 대상으로 한 두 개의 업로드 작업

연결기 없이 동일 폴더가 열려 있으면 `SingletonLock` 또는 `profile_in_use` 오류가 발생합니다. 작성 중인 글이 없는지 확인하고 그 전용 창만 정상 종료한 뒤 다시 `프로필 N 창 열어줘`라고 요청합니다.

## 라운드로빈 배정

원고는 사용자가 입력한 프로필 순서를 그대로 반복합니다.

```text
프로필 순서 2,4,1
원고 1 → 프로필 2
원고 2 → 프로필 4
원고 3 → 프로필 1
원고 4 → 프로필 2
```

실패한 원고를 다른 계정으로 자동 재배정하지 않습니다.

## 여러 PC에서 사용

Git으로 동기화되는 것은 플러그인 코드와 문서뿐입니다. 새 PC에서는 다음을 다시 수행합니다.

1. 저장소와 플러그인 설치
2. 실행 환경 초기화
3. 프로필 슬롯 등록 또는 로컬 기존 프로필 발견
4. 각 프로필 Chrome 열기
5. 각 계정 직접 로그인
6. 각 계정의 `제목을입력해주세요1:` 내 템플릿 확인
7. 로그인·글쓰기 URL 확인

Codex 전용 `browser_profiles`, `naver_profiles.json`, 쿠키와 세션 파일을 GitHub, 메신저 또는 클라우드 드라이브로 공유하지 마십시오.

## 자연어 점검 예시

```text
프로필 목록을 번호, 별칭, 블로그 URL, 글쓰기 URL, 연결기 상태로 보여줘.
```

```text
프로필 1,2 창이 아직 연결돼 있는지 확인하고, 닫혀 있으면 다시 열어줘.
```

```text
프로필 1,2의 로그인 계정과 대상 블로그 소유권, 제목을입력해주세요1: 템플릿을 확인해줘.
```

```text
프로필 1,2 창은 그대로 유지하고 방금 실패한 실행의 미완료 원고만 재개해줘.
```

문제가 생기면 [문제 해결](TROUBLESHOOTING.md)을 참고하고, 내부 CLI가 필요한 경우에만 [개발자·내부 명령](COMMANDS.md)을 사용하십시오.
