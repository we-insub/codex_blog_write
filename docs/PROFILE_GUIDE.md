# 프로필 사용 안내

[README로 돌아가기](../README.md)

네이버 프로필은 브라우저 로그인 상태와 사람이 식별할 수 있는 계정 정보를 분리해 관리합니다. GitHub 저장소에는 둘 다 포함되지 않습니다.

여기서 `naver_N`은 네이버 업로드 전용 로컬 Playwright 프로필입니다. 공개 글을 조사하는 `@Browser`의 내장 프로필이나 cloud 브라우저 프로필과는 별개이며 로그인 상태를 공유하지 않습니다.

## 저장 위치

| 항목 | 기본 위치 | 내용 |
| --- | --- | --- |
| 브라우저 데이터 | `~/.googleblog/browser_profiles/naver_N` | Chrome 로그인 세션과 사이트 데이터 |
| 프로필 목록 | `~/.googleblog/local_agent/naver_profiles.json` | 슬롯, 별칭, 블로그 URL, 확인 상태와 시각 |

Windows에서 `~`는 현재 사용자 홈 폴더입니다. 예를 들면 `C:\Users\사용자이름`입니다.

비밀번호는 어떤 요청이나 설정에도 받거나 저장하지 않습니다. 로그인은 호스트 PC에 표시되는 Chrome 창에서 사용자가 직접 진행합니다.

## 기존 프로필 발견

기존 Mato Helper가 만든 `naver_1`, `naver_2` 같은 폴더를 찾아달라고 Codex에 요청합니다.

```text
기존 네이버 프로필을 찾아서 목록으로 보여줘.
```

발견 작업은 기존 브라우저 데이터를 이동하거나 삭제하지 않습니다. 폴더 번호를 유지해 목록에 추가하고, 알 수 없는 별칭과 블로그 URL은 사용자가 보완할 수 있게 표시합니다.

```text
프로필 번호, 별칭, 블로그 URL과 로그인 확인 상태를 보여줘.
```

## 새 프로필 등록

```text
4번 프로필을 추가해줘. 별칭은 맛집 블로그, 블로그 URL은 https://blog.naver.com/example 이야.
```

- 프로필 번호는 중복되지 않는 1 이상의 번호입니다. 고정된 최대 개수는 없으며 `naver_1`, `naver_2`, `naver_3` 순서로 필요한 만큼 증가시킵니다.
- 별칭은 계정을 알아보기 위한 로컬 표시 이름입니다. 네이버 비밀번호나 인증정보를 넣지 않습니다.
- 블로그 URL은 해당 계정이 작성할 블로그의 기본 URL입니다.

등록 후 우선 프로필 폴더만 검사하도록 요청할 수 있습니다. 이 단계는 Chrome을 열지 않습니다.

```text
4번 프로필 폴더가 준비됐는지만 검사해줘. 브라우저는 열지 마.
```

로그인과 글쓰기 화면 접근까지 확인하려면 이를 명시합니다.

```text
4번 프로필의 네이버 로그인과 글쓰기 접근을 확인해줘.
```

Chrome 창이 열리면 필요한 경우 직접 로그인합니다. 플러그인에 이식된 세션 연결기가 같은 번호의 `naver_N` 영구 프로필을 열고, 로그인 화면에서는 네이버의 정상적인 로그인 상태 유지 옵션을 선택한 뒤 저장된 세션과 글쓰기 접근을 확인합니다. 프로필 폴더를 복사하지 않으며 쿠키·세션 값을 출력하거나 프로필 목록 파일에 저장하지 않습니다. `google-blog-auto`나 Mato Helper 설치본은 필요하지 않습니다.

## 프로필 정보 수정

```text
4번 프로필 별칭을 맛집 메인으로 바꾸고 블로그 URL은 https://blog.naver.com/example 로 설정해줘.
```

별칭과 URL 변경은 브라우저 로그인 세션을 바꾸지 않습니다. 계정 자체가 바뀌었다면 Codex에 로그인 확인을 요청하고 실제 로그인 계정과 블로그 URL이 일치하는지 반드시 확인합니다.

## 목록에서 확인할 정보

```text
네이버 프로필 목록을 표로 보여줘.
```

목록에는 다음 정보가 표시됩니다.

- 프로필 슬롯 번호
- 계정 별칭
- 블로그 URL
- 브라우저 프로필 폴더 존재 여부
- 로그인·글쓰기 화면 최종 확인 상태
- 최종 확인 시각

업로드 전에도 같은 정보를 원고 배정표와 함께 다시 보여줍니다.

## 라운드로빈 배정

```text
원고 10개를 1,2,3번 프로필에 라운드로빈으로 배정한 표만 보여줘. 아직 업로드하지 마.
```

프로필을 입력한 순서가 배정 순서입니다.

```text
원고 1 → 프로필 1
원고 2 → 프로필 2
원고 3 → 프로필 3
원고 4 → 프로필 1
```

한 프로필이 로그인 만료 등으로 실패하면 다른 프로필로 글을 임의 재배정하지 않습니다. 잘못된 블로그로 올라가는 것을 막기 위해 해당 원고를 실패 상태로 남기고 중단 또는 재개 대상으로 표시합니다.

## 프로필별 문체 참고

사용자가 원하면 Codex는 등록된 블로그 URL에 공개된 본인 글 최근 3~5개에서 문장 길이, 말투와 일반적인 구성 특성을 참고할 수 있습니다. 문장을 복제하지 않으며, 참고할 글이 없거나 접근할 수 없으면 자연스러운 정보형 한국어 문체를 사용합니다.

블로그 소유권이 없는 다른 사람의 문체를 사칭하는 용도로 사용하지 않습니다.

## 여러 PC에서 사용

GitHub로 동기화되는 것은 플러그인 코드와 문서뿐입니다. 집 PC에서는 다음 작업을 다시 해야 합니다.

1. 저장소와 플러그인을 설치합니다.
2. Codex에 `Mato Blog Codex 초기 설정해줘`라고 요청합니다.
3. 그 PC에 존재하는 프로필을 찾아달라고 요청하거나 새 번호를 등록합니다.
4. 각 프로필에서 로그인 확인을 요청해 직접 로그인하고 글쓰기 접근을 확인합니다.

브라우저 프로필 폴더나 `naver_profiles.json`을 GitHub에 올려 계정 간에 공유하지 마십시오.

## 로그인 만료와 CAPTCHA

로그인이 만료되면 Codex에 해당 번호의 로그인 확인을 요청해 Chrome을 열고 직접 갱신합니다. 폴더 검사만 요청하면 브라우저를 열지 않습니다. CAPTCHA 또는 접근 제한이 나오면 자동으로 풀거나 우회하지 않습니다. 브라우저를 닫고 충분한 시간 뒤 정상적인 사용자 절차로 다시 확인하십시오.

자세한 복구 방법은 [문제 해결](TROUBLESHOOTING.md)을 참고하십시오.

Python 프로필 명령이 필요한 개발자와 진단 담당자는 [개발자·내부 문제 해결 명령](COMMANDS.md)을 참고하십시오.
