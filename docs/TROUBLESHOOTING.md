# 문제 해결

[README로 돌아가기](../README.md)

문제가 발생하면 먼저 Codex에 실행별 `HISTORY.md`와 `run.json`의 마지막 성공 단계, 오류 요약을 보여달라고 요청합니다.

```text
방금 작업의 히스토리와 마지막 성공 단계, 재개 위치를 보여줘.
```

## `py`, `python3` 또는 Python을 찾을 수 없음

Python 3.10 이상이 설치되어 있는지 확인합니다. 내부 초기 설정기는 기존 전용 가상환경을 먼저 확인하고, Windows에서 `py`·`python`·`python3`, macOS에서 `python3.14`부터 `python3.10`·`python3`·`python`을 순서대로 확인합니다. 설치 후 새 PowerShell 또는 터미널 창을 열고 Codex에 `Mato Blog Codex 초기 설정을 다시 확인해줘`라고 요청합니다.

## Scrapling 또는 Playwright 모듈을 찾을 수 없음

Codex에 로컬 실행 환경을 점검하고 내부 부트스트랩을 다시 수행하도록 요청합니다.

```text
Mato Blog Codex 실행 환경에서 빠진 패키지를 점검하고 초기 설정을 복구해줘.
```

회사 네트워크나 보안 프로그램이 패키지 설치를 막는다면 네트워크 관리자 정책을 확인하십시오. 임의 프록시나 차단 우회 설정을 추가하지 않습니다.

## Codex가 스킬을 찾지 못함

현재 저장소가 마켓플레이스로 등록되어 있는지, 플러그인 이름이 설치 설정과 일치하는지 확인합니다. 설치 절차는 [README](../README.md)를 다시 따릅니다. 마켓플레이스 이름이 `personal`이 아니라면 [마켓플레이스 설정](../.agents/plugins/marketplace.json)의 `name` 값을 사용하고, 설치 후 Codex를 다시 시작합니다.

## Browser 플러그인을 사용할 수 없음

호스트 PC의 Plugins Directory에서 **Browser**가 설치·활성화되어 있는지, Computer Use가 켜져 있는지 확인합니다. 사이트 허용 요청이 표시되면 대상이 네이버 공개 검색 페이지인지 확인한 뒤 승인합니다.

`@Browser`는 Codex 내장 Browser를 가리킵니다. 로컬 `naver_N` 프로필이나 일반 Chrome 로그인 세션을 자동으로 가져오지 않는 것이 정상입니다.

## 모바일 Remote에서 호스트가 보이지 않음

휴대폰과 호스트가 같은 ChatGPT 계정·workspace인지 확인합니다. 호스트 PC는 깨어 있고 온라인이며 데스크톱 앱이 실행 중이어야 합니다. 데스크톱 앱의 Remote Control이 켜져 있는지 확인하고 필요하면 사이드바의 **Set up Remote**에서 QR 코드를 다시 연결합니다.

Windows 또는 macOS에서 `@Browser`나 Computer Use가 필요한 작업은 화면을 잠금 해제 상태로 유지합니다. 전체 설정은 [모바일 Remote 사용 안내](MOBILE_REMOTE.md)를 참고하십시오.

## 기존 프로필이 목록에 없음

```text
이 프로그램에서 전에 만든 네이버 프로필을 다시 찾고 목록과 경로 상태를 보여줘.
```

자동 발견 범위는 이 프로그램 전용 `~/.googleblog/mato-blog-codex/browser_profiles/naver_N`뿐입니다. 마토헬퍼나 일반 Chrome의 프로필은 가져오지 않습니다.

기본 경로 `~/.googleblog/mato-blog-codex/browser_profiles/naver_N` 밖에 있는 프로필은 자동 발견되지 않을 수 있습니다. 마토헬퍼의 `~/.googleblog/browser_profiles`는 Codex가 사용하지 않습니다. 폴더를 임의로 복사하기 전에 Chrome과 다른 자동화 작업을 모두 닫고, 원본을 백업하십시오.

## Chrome 프로필이 사용 중이라는 오류

먼저 Codex에 연결기 상태를 확인하도록 요청합니다.

```text
프로필 1,2 창 연결 상태를 확인하고, 닫혀 있으면 전용 연결기로 다시 열어줘.
```

플러그인의 `profiles.py open`으로 연 창이 살아 있으면 새 Chrome을 실행하지 않고 그 창에 재연결해야 합니다. 연결기 없이 같은 `naver_N` 폴더를 사용하는 Chrome 또는 다른 자동화 작업이 열려 있다면 작성 중인 글이 없는지 확인한 뒤 그 전용 창만 정상 종료하고 다시 엽니다. 작업 관리자에서 강제 종료하기 전에 미저장 원고를 확인하십시오.

동일 프로필로 두 업로드를 동시에 실행하지 않습니다. 원고 업로드는 프로필별로 순차 처리합니다.

## 창을 다시 열 때 로그인이 풀리는 경우

현재 네이버 로그인 화면의 `loginStay` / `nvlong` 체크박스를 선택하고 실제 체크 상태까지 확인합니다. 예전 `keep` 항목도 지원합니다. 단순히 “로그인 상태 유지”라는 문구나 상위 영역을 클릭한 것만으로 성공 처리하지 않습니다.

이전 버전에서 로그인했다면 수정된 전용 창에서 `로그인 상태 유지`를 켜고 한 번 정상 로그인한 뒤, 작업 중인 글이 없는 상태에서 창을 정상 종료하고 같은 프로필을 다시 열어 확인합니다. 네이버 홈과 등록 블로그 글쓰기 화면에 재로그인 없이 접근되는지 검증해야 합니다.

로컬 쿠키의 만료일을 임의로 30일 늘리는 이전 처리는 제거했습니다. 파일이 남아 있어도 서버가 인증을 취소하면 로그인은 유지되지 않습니다. 프로그램은 네이버가 발급한 만료일을 그대로 보존하며, 다른 프로필의 로그인 정보를 복사하지 않습니다.

## 로그인 만료

```text
1번 프로필의 네이버 로그인과 글쓰기 접근을 확인해줘.
```

표시되는 Chrome 창에서 먼저 네이버 홈의 로그인 상태를 확인하고, 이어 글쓰기 화면이 열리는지 확인합니다. 비밀번호를 명령줄, `HISTORY.md` 또는 설정 JSON에 입력하지 마십시오. 네이버가 자동화 브라우저에서 다시 로그인을 요구하면 우회 설정이나 로그인 정보 복사는 하지 않고 정상 로그인 절차를 완료해야 합니다.

폴더 존재만 검사해달라고 요청하면 Chrome을 열지 않습니다.

로그인 확인이 끝난 뒤 다음 작업까지 전용 창을 유지하려면 `프로필 1 창 열어둬`라고 요청합니다. 디스크의 세션은 창을 닫아도 남을 수 있지만 업로드 중 창을 닫으면 현재 연결과 편집 페이지는 즉시 사라집니다.

## 업로드 중 Chrome 창이 닫힘 또는 `TargetClosed`

사용자가 창을 닫거나 대상 Chrome 프로세스가 종료되면 타이핑·표·이미지 입력이 즉시 실패합니다. 발행 버튼을 누르기 전이었다면 보통 공개 글은 없지만 히스토리와 네이버 관리 화면을 함께 확인해야 합니다.

1. 네이버 블로그 관리 화면에서 같은 제목의 임시저장·발행 글이 없는지 확인합니다.
2. Codex에 실패 항목의 상태가 `failed`인지 `uncertain`인지 보여달라고 요청합니다.
3. `프로필 1,2 창 다시 열어줘`라고 요청합니다.
4. 로그인·글쓰기 URL과 템플릿을 다시 확인합니다.
5. `failed`이고 실제 업로드되지 않은 항목만 같은 실행에서 재개합니다.

`uncertain` 항목은 발행 여부를 확인하기 전 자동 재시도하지 않습니다.

## `제목을입력해주세요1:` 템플릿을 찾을 수 없음

업로드 대상 네이버 계정의 Smart Editor에서 **내 템플릿**을 확인합니다.

- 템플릿 이름: `제목을입력해주세요1:`
- 제목용 텍스트 블록: `제목을입력해주세요1`
- 본문 시작 텍스트 블록: `본문2:`

네이버 목록에서는 마지막 콜론이 생략되어 보일 수 있습니다. 템플릿은 계정별이므로 프로필 1에 있다고 프로필 2에서도 보장되지 않습니다.

플러그인은 템플릿이 없으면 기본 편집기의 `글감과 함께 나의 일상을 기록해보세요!` 자리를 찾아 원고를 한 줄씩 타이핑합니다. 전체 본문 복사·붙여넣기나 DOM 삽입은 하지 않습니다. 이 기본 자리까지 찾지 못하면 네이버 편집기 구조가 바뀐 것으로 보고 중단합니다. 템플릿을 사용하는 경우에는 원고에 존재하는 `본문1:`·`인트로1:`·`본문2:` 자리가 템플릿에도 있어야 합니다.

## CAPTCHA 또는 접근 제한

자동화는 즉시 중단하고 히스토리에 원인을 기록합니다. CAPTCHA 해제, 지문 위장, 프록시 전환 또는 접근 제한 우회 기능은 제공하지 않습니다.

브라우저에서 정상적인 사용자 절차를 따르고 충분한 시간 뒤 프로필 상태를 다시 확인하십시오. 반복적으로 제한되면 자동화 실행을 중단하고 네이버 정책을 확인합니다.

## 검색 결과가 0개임

- 검색어에 오타가 없는지 확인합니다.
- `블로그탭`과 `통합검색` 중 의도한 영역인지 확인합니다.
- `@Browser`에서 같은 검색이 정상적으로 보이는지 확인합니다.
- 실행 히스토리에 접근 제한 또는 선택자 변경 오류가 있는지 확인합니다.

통합검색 결과가 5개 미만인 것은 오류가 아닙니다. 화면에 보이는 블로그 글만 사용하며 블로그탭에서 자동 보충하지 않습니다.

## 네이버 화면 구조 변경

수집 결과가 비어 있거나 편집기 요소를 확실히 찾을 수 없으면 안전하게 중단합니다. 화면 좌표를 추측해 클릭하거나 다른 버튼으로 대체하지 않습니다.

플러그인 버전과 오류가 발생한 단계, 민감정보를 제거한 화면 설명을 이슈에 남기십시오. 쿠키, 세션, 전체 `run.json` 또는 개인 블로그 정보는 공개 이슈에 첨부하지 않습니다.

## 원고 검증 실패

```text
방금 생성한 원고를 다시 검증하고 실패한 파일명과 이유를 보여줘.
```

출력된 파일명과 사유를 확인합니다. 흔한 원인은 다음과 같습니다.

- 선택한 템플릿에서 원고에 필요한 본문 영역 자리 누락
- 빈 본문 또는 소제목 구조 누락
- 요청 수보다 파일이 적음
- 중복 제목
- 여러 버전 사이의 과도한 유사성

Codex에 해당 실행 폴더와 검증 오류를 알려 원고를 수정한 뒤 다시 검사합니다. 검증 실패 상태로 업로드하지 않습니다.

## 업로드가 실행되지 않음

Codex는 업로드 전에 프로필, 블로그 URL, 원고 제목, 저장 방식과 내부 실행 서명을 확인합니다. 사용자의 같은 요청에 프로필과 임시저장 또는 발행 의도가 이미 들어 있다면 정상 상태에서는 별도 승인 질문 없이 실행까지 이어져야 합니다.

```text
방금 요청한 프로필과 방식 그대로 미완료 업로드를 계속 진행해줘. 실행 ID는 내부 기록을 사용해.
```

공개 발행은 사용자가 `발행`, `바로발행`, `자동발행`처럼 의도를 명시하면 같은 요청에서 진행합니다. 실행 식별자나 검증 파일이 중간에 바뀌면 자동으로 중단하고 새 계획을 만들지만, 정상 계획에서는 동일 승인을 반복해 묻거나 사용자에게 실행 ID를 입력하게 하지 않습니다.

## 일부 글만 성공하고 중단됨

`HISTORY.md`에서 원고별 결과와 마지막 성공 항목을 확인합니다. 로그인 또는 편집기 문제를 해결한 후 Codex에 같은 실행, 프로필 순서와 저장 방식으로 재개하도록 요청합니다.

재개 시 `run.json`에서 성공으로 확정된 항목은 건너뛰고 대기·실패 항목만 처리합니다. 성공 여부가 불명확하면 중복 발행을 피하기 위해 네이버 블로그 관리 화면에서 먼저 확인합니다.

히스토리에 `uncertain`으로 표시된 항목은 확인 전에는 자동 재시도되지 않습니다. 네이버에서 직접 확인한 뒤 다음처럼 Codex에 알려주십시오.

```text
방금 uncertain으로 멈춘 2번 원고가 네이버에 저장되지 않은 것을 확인했어. 표시된 실행 ID와 엔트리 키로 미업로드 상태를 확정하고 그 항목부터 재개해줘.
```

실제 공개 발행을 확인했다면 해당 글의 직접 네이버 URL도 함께 알려야 합니다. Codex는 정확한 원고 번호·엔트리 키·실행 ID가 일치할 때만 로컬 상태를 바꿉니다.

## 잘못된 프로필로 배정됨

실행하지 말고 프로필 목록을 수정합니다.

```text
프로필 목록을 보여줘. 2번 별칭과 블로그 URL을 수정한 뒤 로그인 계정까지 확인해줘.
```

그 후 업로드 계획을 다시 출력합니다. 이미 잘못 발행한 글의 삭제나 수정은 외부 상태를 바꾸는 작업이므로 네이버 관리 화면에서 대상을 정확히 확인해 직접 처리합니다.

## 히스토리를 쓸 수 없음

사용자 홈의 `~/.googleblog/mato-blog-codex/`와 실행 폴더에 현재 Windows 또는 macOS 계정이 쓸 수 있는지 확인합니다. 랜섬웨어 보호, macOS 개인정보 보호 설정 또는 회사 보안 정책이 차단하는 경우 허용 여부를 관리자에게 확인하십시오.

히스토리를 쓸 수 없는 상태에서는 안전한 재개와 결과 확인이 어려우므로 업로드를 진행하지 않습니다.

## 이미지 관련 요청

출처 이미지 다운로드는 플러그인에 포함된 네이버 URL 다운로드 기능으로 수행하며 출처 URL과 `image_N.jpg` 태그를 함께 유지합니다. 본인 소유 또는 사용 허가가 확인된 이미지는 원고별 폴더에서 태그 순서대로 Smart Editor 사진 버튼을 통해 업로드합니다.

이미지 태그와 실제 JPEG가 1:1로 일치하지 않으면 원고 검증에서 중단합니다. 파일 선택 창, 업로드 버튼 또는 편집기 포커스를 확인할 수 없을 때도 해당 이미지를 건너뛰고 발행하지 않습니다.

중복 감지 회피용 픽셀 변조, 허위 EXIF·촬영일·위치 생성과 출처 은폐는 지원하지 않습니다. 이미지 사용 범위는 본인 소유, 명시적으로 사용 허가를 받은 이미지 또는 적법하게 생성한 이미지로 제한합니다.

## 개발자·내부 진단

위의 자연어 복구로 해결되지 않을 때만 [개발자·내부 문제 해결 명령](COMMANDS.md)을 사용합니다. 내부 명령은 일반 사용자 인터페이스가 아니며, 업로드 실행·발행 확인 옵션을 임의로 우회해서는 안 됩니다.
