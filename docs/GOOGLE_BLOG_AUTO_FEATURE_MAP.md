# Google Blog Auto 기능 추출 맵

[README로 돌아가기](../README.md)

이 문서는 `C:\Users\USER\Desktop\google-blog-auto`의 **생성모델**과 **N 블로그** 영역을 Mato Blog Codex로 옮기기 위해 만든 기능 인벤토리이자 현재 이식 상태표다. 원본 파일은 수정하지 않고 읽기만 해 비교한다.

`유지`는 Codex 자연어 워크플로에 넣을 기능, `보류`는 사용자가 필요성을 확인한 뒤 넣을 기능, `제외`는 현재 Mato Blog Codex의 확정 범위 밖인 기능이다. 이 표를 위에서 아래로 검토해 제거해도 전체 흐름이 끊기지 않게 한다.

## 1. 생성모델

| 기능 | 원본 위치 | 상태 | Codex에서의 형태 |
| --- | --- | --- | --- |
| 글 생성 모델 선택 | `1_프로그램/app.py` / 생성모델 화면 | 유지 | 별도 모델 선택 화면 대신 현재 Codex가 원고 생성 담당 |
| 이미지 생성 모델 선택 | 같은 위치 | 보류 | 이미지 기능을 별도 확장할 때만 사용 |
| 텍스트·이미지 모델 목록과 별칭 정리 | `app.py` 모델 목록·자동 보정 | 보류 | Codex 모델을 바꾸는 기능이 아니라, 향후 외부 모델 연결 시에만 필요 |
| 사용자 정의 모델 목록 병합 | `custom_models.json` 처리 | 보류 | 외부 API 키 기반 모델 연결을 선택할 때만 구현 |
| 모델 선택 자동 저장 | `app.py` 모델 변수 변경 처리 | 제외 | Codex가 생성 모델이므로 사용자별 API 모델 저장 불필요 |
| 로컬 AI CLI 모델 탐색 | `local_agent/agent.py` 모델 탐색 처리 | 보류 | 사용자가 로컬 모델 연결을 요구할 때 별도 설계 |

## 2. N 블로그 화면 전체

원본의 N 블로그 탭은 `글작성`, `설정`, `글변환규칙`, `글변환`, `AI 글 작성`, `역순작성`, `역순사진`과 관리자 전용 탭으로 구성된다.

### 2-1. 설정·프로필

| 기능 | 원본 위치 | 상태 | Codex에서의 형태 |
| --- | --- | --- | --- |
| `naver_1`~`naver_3` 프로필 폴더 | `_naver_main.py` 프로필 설정 | 유지 | `~/.googleblog/browser_profiles/naver_N` |
| 프로필 선택·별칭 표시 | 같은 위치 | 유지 | 자연어의 `1번 프로필`과 로컬 프로필 카탈로그 |
| 일반 Chrome 로그인창 열기 | 프로필 로그인 처리 | 유지 | 사용자가 직접 로그인하는 표시 Chrome 창 |
| 네이버 홈 뒤 글쓰기 주소 확인 | 프로필 확인 처리 | 유지 | 프로필 확인 시 홈 → 지정 글쓰기 URL |
| 블로그 URL·글쓰기 URL·별칭 저장 | URL 슬롯 처리 | 유지 | 로컬 메타데이터에 번호·별칭·URL만 저장 |
| URL 글쓰기 모드 | 설정 탭 | 유지 | 프로필 대신 지정 URL 대상으로 임시저장할 수 있는 후속 모드 |

| 프로필 초기화 | 프로필 초기화 처리 | 보류 | 로그인 프로필 삭제는 명시적 사용자 요청과 별도 확인 후에만 제공 |
| 브라우저 로그인 세션 연결 | `NaverPlaywright.login()`의 영구 프로필 로그인 유지 처리 | 구현 | `naver_session.py`와 `profiles.py`로 이식. 같은 `naver_N` 안에서만 유지하고 인증값은 출력하지 않음 |

원본에는 별도 메뉴 또는 로컬 에이전트 작업으로 다음 기능도 있다. 본 문서의 1차 목표인 “검색 → 원고 → 임시저장/발행”과는 분리해 필요할 때 추가한다.

| 기능군 | 원본 처리 | 상태 |
| --- | --- | --- |
| 네이버 키워드 조회 | `naver_keyword_lookup` | 보류 |

| 내 블로그 문체 분석 | `naver_style_analysis` | 유지 |

| 네이버 카페 업로드 | `naver_cafe_upload` | 제외 |

## 4. Codex 최종 흐름

```text
자연어 요청
  → 프로필·URL·생성 개수·저장 방식 해석
  → Browser 공개 검색 또는 사용자가 준 원문
  → 분석·문체 적용·원고 N개 생성
  → Mato `_함축.txt` 검증/변환
  → 프로필 라운드로빈 배정표 확인
  → 임시저장 또는 명시적 발행
  → HISTORY.md / run.json 기록 및 재개 가능 상태 저장
```

## 5. 다음 구현 순서

1. 이미 있는 프로필·검색·원고·변환·히스토리 기능을 원본 기준으로 맞춘다.
2. `글작성`의 프롬프트 조합과 역순작성 기능을 자연어 명령으로 추가한다.
3. 업로드는 임시저장부터 실제 화면 검증을 통과시킨다.
4. 필요성이 확인된 보류 항목만 하나씩 추가한다.
