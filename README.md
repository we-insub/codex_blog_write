# Mato Blog Codex 사용설명서

Mato Blog Codex는 네이버 공개 검색 결과, 사용자가 지정한 본인 글 또는 마이리얼트립 상품 페이지를 바탕으로 Codex가 한국어 블로그 원고를 만들고, PC에 저장된 번호별 Chrome 프로필로 네이버 블로그에 임시저장하거나 발행하는 Codex 플러그인입니다.

일반 사용자는 Python 명령을 직접 실행하지 않습니다. Codex 데스크톱 앱에서 `프로필 1 만들어줘`, `프로필 1,2 창 열어둬`, `이 URL 글로 새 글 2개 만들어서 프로필 1,2에 바로 발행해줘`처럼 자연어로 요청하면 됩니다.

이 플러그인은 Mato Helper 또는 `google-blog-auto` 설치본 없이 독립적으로 실행됩니다. 공유되는 것은 플러그인 코드뿐이며 네이버 로그인 세션, 쿠키, 계정 비밀번호, 생성 원고와 실행 기록은 각 PC의 로컬 폴더에만 저장됩니다.

## 처음 설치한 뒤 해야 할 일

처음 사용하는 PC에서는 다음 순서로 준비합니다.

1. 저장소와 플러그인을 설치합니다.
2. Codex에서 초기 설정을 실행합니다.
3. 사용할 네이버 블로그마다 번호별 프로필을 등록합니다.
4. 프로필별 전용 Chrome 창을 열고 사용자가 직접 로그인합니다.
5. 각 네이버 계정에 `제목을입력해주세요1:` 템플릿이 있는지 확인합니다. 없어도 기본 편집기로 입력할 수 있습니다.
6. 로그인과 글쓰기 URL을 확인한 뒤 Chrome 창을 열어둡니다.
7. 생성·임시저장 또는 발행 작업을 요청합니다.

가장 중요한 운영 규칙은 다음 두 가지입니다.

> 프로필 생성만으로는 Chrome이 열리지 않습니다. 생성 후 `프로필 1,2 창 열어둬`라고 별도로 요청해야 합니다.

> 업로드가 시작된 뒤 결과 URL 확인이 끝날 때까지 해당 프로필 Chrome 창을 직접 닫지 마십시오. 창을 닫으면 진행 중인 타이핑·이미지 삽입·발행 확인이 즉시 중단됩니다.

> 프로필 생성·정보 수정·플러그인 업데이트는 기존 로그인 폴더를 초기화하지 않습니다. 초기화는 사용자가 정확한 프로필 번호를 명시하고 `RESET-N` 확인을 제공한 경우에만 수행됩니다. 네이버가 서버에서 세션을 만료시키는 경우에는 같은 프로필에서 정상 재로그인이 필요할 수 있습니다.

## 요구 사항

- Windows 10/11 또는 macOS
- Google Chrome
- Git
- 최신 ChatGPT/Codex 데스크톱 앱
- Codex의 Browser 플러그인과 Computer Use
- Python 3.10 이상 (`py` 또는 `python`/`python3`)

네이버 비밀번호는 플러그인에 입력하지 않습니다. 처음 로그인하거나 세션이 만료됐을 때 표시되는 전용 Chrome 창에서 사용자가 직접 정상 로그인합니다.

### 지원 운영체제

현재 배포 버전은 **Windows 10/11과 macOS**를 지원합니다. 운영체제별 차이는 플러그인이 내부에서 처리합니다.

- Chrome: Windows의 표준 설치 경로와 macOS의 `/Applications`·사용자 `Applications`를 탐색
- Python 환경: Windows는 `.venv/Scripts/python.exe`, macOS는 `.venv/bin/python` 사용
- 링크카드 붙여넣기: Windows는 `clip`·`Control+V`, macOS는 `pbcopy`·`Command+V` 사용
- 프로필 창: Windows와 macOS 모두 로컬 전용 DevTools 연결기로 같은 영구 프로필에 재연결

Chrome과 Python 3.10 이상은 각 PC에 먼저 설치해야 합니다. 새 PC에서는 운영체제와 관계없이 프로필별 최초 로그인을 한 번 수행합니다.

## 처음 공유받은 사용자의 설정 목록

처음 설치한 사용자가 직접 준비하거나 결정해야 하는 값은 다음과 같습니다.

| 구분 | 사용자가 설정할 값 | 필수 여부 | 설정 시점 |
| --- | --- | --- | --- |
| 실행 환경 | Windows 10/11 또는 macOS, Chrome, Git, Codex, Python 3.10 이상 | 필수 | PC당 1회 |
| 네이버 프로필 | 프로필 번호, 별칭, 블로그 ID 또는 기본 블로그 URL | 필수 | 계정당 1회 |
| 네이버 로그인 | 각 전용 Chrome에서 직접 로그인하고 로그인 상태 유지 선택 | 필수 | 계정당 최초 1회 및 세션 만료 시 |
| 블로그 소유권 | 로그인 계정이 등록한 블로그의 실제 소유자인지 확인 | 필수 | 프로필 확인 시 |
| 내 템플릿 | `제목을입력해주세요1:` 템플릿과 원고 영역 | 권장 | 네이버 계정당 1회 |
| 공통 프롬프트 | `공통.txt`의 말투·구조·표·줄바꿈 규칙 검토 | 권장 | PC당 1회 |
| 작업 옵션 | 검색 영역, 원고 수, 프로필 순서, 임시저장 또는 발행 | 작업별 | 요청할 때 |

다음 값은 사용자가 계산하거나 입력하지 않습니다.

- 네이버 글쓰기 URL: 블로그 ID 또는 기본 블로그 URL에서 자동 생성
- Chrome 프로필 폴더: 프로필 번호에 맞춰 자동 생성
- 원고·이미지·히스토리 저장 경로: 실행할 때 자동 생성
- 타이핑 속도와 표 대기 시간: 코드에 고정
- 원고별 프로필 배정: 요청한 프로필 순서로 자동 배정
- 로그인 쿠키와 비밀번호: 설정 파일이나 Git에 저장하지 않음

새 PC에는 다른 PC의 로그인 세션이 전달되지 않습니다. 같은 저장소를 설치하더라도 프로필 등록과 네이버 로그인은 PC마다 다시 해야 합니다.

## 설치

GitHub에서 저장소를 복제합니다. 비공개로 배포하는 경우에는 접근 권한이 있는 계정이 필요합니다.

```shell
git clone https://github.com/we-insub/codex_blog_write.git
cd codex_blog_write
```

저장소를 Codex 로컬 마켓플레이스로 등록하고 플러그인을 설치합니다.

```shell
codex plugin marketplace add "$PWD"
codex plugin add mato-blog-codex@personal
```

Codex를 다시 시작한 뒤 다음처럼 요청합니다.

```text
Mato Blog Codex 초기 설정하고 실행 환경을 확인해줘.
```

Codex가 `~/.googleblog/mato-blog-codex/.venv`에 이 플러그인 전용 Python 환경을 준비합니다. 일반 사용자는 내부 경로나 Python 명령을 기억할 필요가 없습니다.

## 프로필의 의미

`프로필 1`, `프로필 2`는 각각 서로 다른 Chrome 사용자 데이터 폴더입니다.

```text
프로필 1 → ~/.googleblog/mato-blog-codex/browser_profiles/naver_1
프로필 2 → ~/.googleblog/mato-blog-codex/browser_profiles/naver_2
프로필 N → ~/.googleblog/mato-blog-codex/browser_profiles/naver_N
```

프로필마다 다음 정보가 분리됩니다.

- 네이버 로그인 세션
- 해당 계정의 사이트 데이터
- 사용자가 알아보기 위한 별칭
- 대상 블로그 URL
- 자동 생성된 네이버 글쓰기 URL
- 마지막 로그인·글쓰기 확인 상태

프로필 번호에는 코드상 고정 최대 개수가 없습니다. `naver_1`부터 필요한 만큼 `naver_N`을 만들 수 있습니다. 다만 전용 Chrome 창을 많이 열수록 메모리를 사용하므로, 현재 작업에 사용할 프로필만 열어두는 것을 권장합니다.

Codex의 공개 검색용 `@Browser`와 네이버 업로드용 `naver_N` Chrome은 서로 다른 브라우저입니다. 어느 한쪽에 로그인해도 다른 쪽으로 로그인 상태가 전달되지 않습니다.

## 프로필 1개 만들기

블로그 ID가 `intp_kr`이면 다음 중 하나로 요청할 수 있습니다.

```text
프로필 1 생성해줘. 별칭은 intp_kr이고 블로그 URL은 https://blog.naver.com/intp_kr 이야.
```

```text
프로필 1 생성해줘. 별칭은 intp_kr이고 블로그 ID는 intp_kr 이야.
```

플러그인은 입력값을 아래 주소로 정규화합니다.

| 항목 | 저장값 |
| --- | --- |
| 블로그 URL | `https://blog.naver.com/intp_kr` |
| 글쓰기 URL | `https://blog.naver.com/intp_kr?Redirect=Write&` |
| Chrome 폴더 | `~/.googleblog/mato-blog-codex/browser_profiles/naver_1` |

글쓰기 URL은 블로그 URL 또는 ID에서 자동 생성됩니다. 사용자가 `Redirect=Write` 주소를 따로 계산하거나 입력할 필요는 없습니다.

## 프로필 N개 만들기

프로필마다 블로그 ID 또는 기본 블로그 URL을 한 개씩 지정합니다. 예를 들어 프로필 1과 2를 만들려면 다음처럼 요청합니다.

```text
네이버 프로필 2개 만들어줘.
프로필 1은 별칭 intp_kr, URL https://blog.naver.com/intp_kr
프로필 2는 별칭 youtube_intp, URL https://blog.naver.com/youtube_intp
```

결과는 다음과 같습니다.

| 프로필 | 별칭 | 블로그 URL | 글쓰기 URL |
| --- | --- | --- | --- |
| 1 | `intp_kr` | `https://blog.naver.com/intp_kr` | `https://blog.naver.com/intp_kr?Redirect=Write&` |
| 2 | `youtube_intp` | `https://blog.naver.com/youtube_intp` | `https://blog.naver.com/youtube_intp?Redirect=Write&` |

프로필을 5개 이상 만들 때도 같은 형식으로 번호·별칭·URL 목록을 한 번에 전달하면 Codex가 번호별로 등록합니다. 이미 존재하는 번호는 자동 덮어쓰지 않고 수정 대상으로 처리합니다.

기본 블로그 URL 대신 `intp_kr` 같은 블로그 ID나 `https://m.blog.naver.com/intp_kr` 주소를 줘도 데스크톱 기본 URL로 정규화됩니다. 대상 혼동을 줄이려면 개별 글 URL보다 `https://blog.naver.com/<블로그ID>` 형식을 권장합니다.

## 기존 프로필 찾기

이미 이 PC에 `naver_1`, `naver_2` 같은 영구 프로필이 있다면 새로 만들지 않고 발견할 수 있습니다.

```text
이 프로그램에서 전에 만든 네이버 프로필을 찾아서 번호, 별칭, 블로그 URL, 마지막 로그인 확인 상태를 보여줘.
```

발견은 브라우저 폴더를 복사하거나 쿠키를 읽어 출력하지 않습니다. 기존 폴더와 같은 번호를 프로필 목록에 연결할 뿐입니다. 다른 PC로 옮긴 프로필이나 일반 Chrome 프로필은 자동으로 공유되지 않습니다.

## 전용 Chrome 창 열기와 로그인

프로필을 등록한 뒤 선택한 창을 엽니다.

```text
프로필 1,2 Chrome 창을 각각 열어두고 닫지 마.
```

플러그인은 각 `naver_N` 폴더를 전용 Chrome 창으로 열고, PC 내부의 loopback 연결기를 함께 시작합니다. 이후 로그인 확인과 업로드는 새 브라우저를 중복 실행하지 않고 이 열린 창에 다시 연결합니다.

처음 열었을 때 각 창에서 다음을 완료합니다.

1. 해당 프로필에 연결할 네이버 계정으로 직접 로그인합니다.
2. 네이버의 정상적인 로그인 상태 유지 옵션을 선택합니다. 새로 연 프로필 창에서는 이 선택을 먼저 준비하며, 네이버가 재사용 가능한 로그인 상태를 저장했을 때만 로그인 완료로 처리합니다.
3. 등록한 블로그의 글쓰기 주소가 열리는지 확인합니다.
4. 로그인된 계정이 등록한 블로그의 실제 소유자인지 확인합니다.
5. 작업이 끝날 때까지 창을 열어둡니다.

로그인 후 Codex에 확인을 요청합니다.

```text
프로필 1,2의 로그인 상태와 각 글쓰기 URL을 확인해줘. Chrome 창은 계속 열어둬.
```

`ready`가 확인돼야 업로드를 시작합니다. 프로필 폴더만 존재하는지 보고 싶고 Chrome을 열고 싶지 않다면 다음처럼 요청합니다.

```text
프로필 1 폴더만 확인해줘. 로그인 창은 열지 마.
```

### Chrome 창을 언제 닫아도 되나

- 프로필 등록 직후: 아직 창이 없으므로 `열어둬` 요청이 필요합니다.
- 로그인 완료 후, 작업 시작 전: 닫아도 로그인 데이터는 프로필 폴더에 남지만 다음 작업 전에 다시 열어야 합니다.
- 원고 입력·이미지 업로드·임시저장·발행 중: 절대 닫지 마십시오.
- 임시저장·발행 완료 URL과 기록을 확인한 뒤: 플러그인은 창을 자동으로 닫지 않고 대기 상태로 유지합니다. 전체 작업 완료 후에 사용자가 닫을 수는 있습니다.

창을 닫는다고 로그인 데이터가 즉시 삭제되지는 않습니다. 그러나 실행 중인 연결은 끊기므로 현재 작업은 실패합니다. 다음 작업에서는 `프로필 1,2 창 다시 열어줘`라고 요청하면 같은 영구 프로필을 다시 엽니다.

같은 `naver_N` 폴더를 일반 Chrome 명령이나 다른 자동화 프로그램으로 동시에 열지 마십시오. 연결기 없이 같은 폴더가 이미 열려 있으면 프로필 잠금 오류가 발생할 수 있습니다. 이 경우 작성 중인 글이 없는지 확인한 뒤 해당 전용 창만 닫고 Codex에 다시 열어달라고 요청합니다.

## 네이버 내 템플릿 준비

현재 업로더는 Mato Helper와 같은 흐름으로 네이버 Smart Editor의 **내 템플릿**을 먼저 불러옵니다. 가장 안정적인 입력을 위해 각 네이버 계정에 다음 템플릿을 한 번씩 만들어 두는 것을 권장합니다. 템플릿 자체가 없으면 Mato Helper와 같이 기본 편집기의 `글감과 함께 나의 일상을 기록해보세요!` 자리로 전환해 같은 줄 단위 타이핑을 수행합니다.

| 설정 | 값 |
| --- | --- |
| 템플릿 이름 | `제목을입력해주세요1:` |
| 제목용 텍스트 블록 | `제목을입력해주세요1` |
| 본문 시작 텍스트 블록 | `본문2:` |
| 선택 본문 텍스트 블록 | `본문1:` |
| 선택 인트로 텍스트 블록 | `인트로1:` |

`본문1:` 또는 `인트로1:` 영역이 있는 원고를 사용할 때는 템플릿에도 같은 이름의 텍스트 블록을 추가합니다. 업로더는 `본문1:` → `인트로1:` → `본문2:` 순서로 각 영역을 따로 찾아 입력합니다.

네이버 템플릿 목록에서는 마지막 콜론이 생략되어 `제목을입력해주세요1`로 보일 수 있으며 플러그인은 두 표시를 같은 이름으로 인식합니다.

업로드 순서는 다음과 같습니다.

1. 템플릿 버튼을 누릅니다.
2. `내 템플릿` 탭을 엽니다.
3. `제목을입력해주세요1:` 템플릿을 선택합니다.
4. 제목을 50ms 지연으로 실제 타이핑합니다.
5. 템플릿의 제목 자리와 원고에 사용된 `본문1:`·`인트로1:`·`본문2:` 자리를 각각 교체합니다.
6. 일반 문장과 표 셀은 20ms 고정 지연으로 한 줄씩 실제 타이핑합니다.
7. `ㅂㅂㅂ`·`소제목`은 인용구, `!!`는 구분선, 표 마커는 Smart Editor 표로 처리합니다.
8. 이미지 태그는 사진 버튼으로 올리고, URL 한 줄만 운영체제 클립보드로 붙여넣어 네이버 링크카드 생성을 기다립니다.
9. 임시저장 또는 발행 버튼을 누르고 성공 상태를 확인합니다.

원고 전체를 클립보드로 붙여넣거나 본문 DOM에 직접 삽입하지 않습니다. 템플릿이 없을 때도 기본 편집기에 원고를 한 줄씩 실제 타이핑합니다. 다만 선택된 템플릿 안에서 원고에 필요한 `본문1:`·`인트로1:`·`본문2:` 자리를 찾지 못하면 잘못된 위치에 입력하지 않고 중단합니다.

템플릿 이름과 텍스트 블록 이름은 현재 별도 설정 화면에서 바꾸는 값이 아니라 업로더에 고정된 값입니다. 다른 이름의 템플릿을 만들면 선택하지 않고 기본 빈 편집기로 전환합니다. Mato Helper와 같은 템플릿 흐름을 사용하려면 위 이름을 정확히 사용하십시오.

## 글쓰기 속도와 고정 대기값

글쓰기 속도는 최초 사용자가 설정할 항목이 아닙니다. 현재 업로더에는 다음 값이 고정되어 있습니다.

| 동작 | 현재 값 | 사용자 설정 필요 |
| --- | ---: | --- |
| 제목 타이핑 | 글자당 50ms | 없음 |
| 일반 본문 타이핑 | 글자당 20ms | 없음 |
| 표 셀 타이핑 | 글자당 20ms | 없음 |
| 템플릿 자리 교체 | 글자당 30ms | 없음 |
| 표 생성 후 대기 | 1.5초 | 없음 |
| 표 선택·삭제 대기 | 2.5초 | 없음 |
| 마이리얼트립 상품 URL 링크카드 | URL 한 줄마다 2초 | 없음 |
| 같은 프로필의 다음 글 대기 | 기본 3초 | 없음 |

Mato Helper의 `글쓰기 속도 20`에 대응하는 일반 본문과 표 셀 입력은 20ms 고정입니다. 제목은 안정적인 제목 영역 교체를 위해 50ms, 템플릿 자리 교체는 30ms로 별도 고정되어 있습니다. “제목을 포함한 모든 타이핑을 20ms”로 바꾸려면 사용자 설정이 아니라 코드 변경이 필요합니다.

여러 프로필 업로드는 `프로필 1 완료 → 프로필 1 창 유지 → 프로필 2 완료 → 프로필 2 창 유지 → 프로필 3 완료` 순서로 직렬 실행합니다. 이는 네이버의 필수 조건이 아니라 전역 클립보드 충돌, 편집기 타이밍 오류, 프로필별 성공 URL과 재개 상태 혼선을 줄이기 위한 안정성 정책입니다. 마지막 프로필의 Chrome 창도 자동 종료하지 않습니다.

## 공통 글쓰기 프롬프트 설정

첫 원고 생성 시 다음 PC 로컬 파일이 자동 생성됩니다.

```text
~/.googleblog/mato-blog-codex/prompts/공통.txt
```

사용자는 필요할 때 이 파일에서 다음 규칙을 조정할 수 있습니다.

- 글의 말투와 문장 종결 방식
- 모바일 줄바꿈과 문단 길이
- 인트로·목차·본문·마무리 구조
- 소제목과 표 생성 규칙
- 정보와 경험의 비율
- 금지 표현과 제목 유지 규칙
- 이미지 태그 순서와 배치 규칙

`공통.txt`는 Git에 포함되지 않는 PC별 사용자 파일입니다. 한 PC에서 수정한 긴 공통 프롬프트는 저장소를 공유해도 다른 사용자에게 전달되지 않으며, 새 사용자는 플러그인 코드에 포함된 기본 프롬프트로 시작합니다. 모든 사용자가 같은 작성 규칙을 사용해야 한다면 배포 전에 프로젝트의 기본 프롬프트를 원하는 내용으로 갱신하거나, 별도의 안전한 초기 설정 절차로 동일한 프롬프트를 배포해야 합니다.

공통 프롬프트에는 로그인 정보, 쿠키, 비밀번호 또는 개인 식별 정보를 넣지 마십시오.

## 가장 빠른 정상 사용 예시

프로필 준비가 끝난 뒤 다음처럼 요청합니다.

```text
"서울 맛집" 블로그탭으로 원고 2개 만들고 프로필 1,2에 임시저장해줘.
```

옵션을 생략하면 다음 기본값을 사용합니다.

| 항목 | 기본값 |
| --- | --- |
| 검색 영역 | 통합검색 |
| 생성 수 | 10개 |
| 업로드 방식 | 임시저장 |
| 프로필 없음 | 파일만 생성하고 업로드하지 않음 |

이 표의 값은 최초 설치 설정이 아니라 작업 요청에 값을 쓰지 않았을 때 적용되는 작업별 기본값입니다. 공개 발행은 기본값으로 저장할 수 없으며, 실제 공개를 원할 때 요청에 `발행`, `바로발행` 또는 `자동발행`을 명시해야 합니다.

따라서 다음 요청은 통합검색, 원고 10개, 프로필 1 임시저장으로 해석합니다.

```text
프로필 1 "서울 맛집"
```

원고 수를 적으면 정확히 그 수만큼 만듭니다.

```text
"서울 맛집" 블로그탭, 원고 3개, 프로필 1,2에 임시저장
```

### 마이리얼트립 상품 원고 1개

상품 URL이 포함된 요청은 네이버 전용 원고 1개를 만드는 별도 흐름입니다. 업체 제공 상품 이미지를 사용하려면 현재 요청에서 사용 권한을 명시해야 합니다.

```text
https://myrealt.rip/iZRp3d
메인키워드: 베트남 나트랑 투어
서브키워드: 아이랑, 부모님이랑, 비용
후킹: 솔직후기
동행: 시부모님, 아이 둘
업체 제공 상품 이미지 사용권한 있음
프로필 1 임시저장
```

Codex는 상품 페이지의 펼침·갤러리·끝 스크롤을 증명하고 전용 분류기의 정확한 Browser 후보 인덱스로 다시 확인한 뒤, 현재 상품 판매자 이미지 전부를 중복 없이 사용합니다. 후기 사진, 추천·다른 상품과 UI 이미지는 제외합니다. 각 사진의 시각 요약과 제목을 비교해 대표 사진을 고르고 나머지는 상품소개·코스 문단에 분산합니다. 입력 URL은 `본문2:` 처음과 끝에 정확히 두 번 들어가며 링크카드마다 2초 기다립니다. 동행 정보나 후기를 실제 사용자 경험으로 바꾸지 않으며, 1인칭 체험은 사용자가 별도로 제공한 `경험노트` 사실 범위에서만 작성합니다. 자세한 검증 순서는 [전체 작업 흐름](docs/WORKFLOW.md#3a-마이리얼트립-상품-url-분기)을 참고하십시오.

## 바로 발행

공개 발행을 원하면 요청에 `발행`, `바로발행` 또는 `자동발행`을 명시합니다.

```text
https://m.blog.naver.com/intp_kr/224348902627
내 글을 내려받아 새 글 2개로 재생성하고 프로필 1,2에 삽입한 뒤 바로 발행해줘.
```

이 표현은 실제 공개 발행 승인입니다. Codex는 대상 프로필, 원고 해시와 내부 실행 서명을 확인한 뒤 같은 작업에서 중간 재질문 없이 발행까지 진행합니다. 발행이 끝나면 프로필별 글 제목과 확인된 공개 URL을 보고합니다.

`업로드하지 마`, `파일만 만들어줘`라고 하면 프로필 번호가 포함돼 있어도 네이버에 쓰지 않습니다.

## 여러 프로필의 원고 배정

원고는 사용자가 적은 프로필 순서대로 라운드로빈 배정됩니다.

```text
원고 1 → 프로필 1
원고 2 → 프로필 2
원고 3 → 프로필 3
원고 4 → 프로필 1
```

한 프로필이 실패해도 다른 계정으로 임의 재배정하지 않습니다. 잘못된 블로그 발행을 막기 위해 해당 원고를 실패 또는 재개 대상으로 기록합니다.

## 공개 검색과 본인 글 재생성

### 네이버 공개 검색

```text
"제주 렌터카" 통합검색에서 보이는 블로그 글을 분석해 원고 3개 만들어줘. 아직 업로드하지 마.
```

Codex의 `@Browser`가 선택한 검색 영역에 실제로 노출된 네이버 블로그 글을 순서대로 최대 5개 확인합니다. 통합검색에 글이 2개만 보이면 2개만 사용하고 블로그탭 결과로 몰래 보충하지 않습니다.

### 본인 글 URL

```text
내 글 URL의 이미지 다운로드 → 사진 메타데이터 정리 → 새 원고 3개 생성
```

본인 소유 또는 사용 허가된 이미지에 한해 각 원고 폴더에 독립된 `image_N.jpg` 데이터셋을 만들 수 있습니다. EXIF 방향을 적용하고 GPS·EXIF·XMP·ICC를 제거한 뒤 `image-processing.json`에 값이 아닌 처리 여부와 해시만 기록합니다.

다른 사람의 이미지는 소유권 또는 사용 허가 확인 없이 업로드하지 않습니다. 허위 촬영일·위치·카메라 정보 생성, 픽셀 은닉 변조와 CAPTCHA 우회는 지원하지 않습니다.

## 원고 형식

검증된 원고는 다음 Mato `_함축.txt` 형식을 사용합니다.

```text
제목을입력해주세요1: 글 제목

본문2:
도입 문단

ㅂㅂㅂ첫 번째 소제목
본문 문단

[image_1.jpg]
```

표는 다음 구조로 Smart Editor 표 블록으로 변환됩니다.

```text
표 3 x 2 시작
(0,0) 항목
(0,1) 내용
(1,0) 예시
(1,1) 설명
(2,0) 확인
(2,1) 완료
표 3 x 2 끝
```

업로드 전 파일 수, 제목·본문 마커, 소제목, 이미지 태그와 JPEG의 1:1 대응, 원고 간 과도한 유사성, 파일 SHA-256을 검사합니다. 검증 뒤 원고가 바뀌면 다시 검증해야 합니다.

## 중단과 재개

다음 상황에서는 자동 우회 없이 중단합니다.

- 로그인 만료
- CAPTCHA 또는 접근 제한
- 등록 블로그와 로그인 계정의 소유권 불일치
- 선택된 템플릿에서 원고에 필요한 `본문1:`·`인트로1:`·`본문2:` 자리 누락
- 편집기 버튼·표·이미지 업로드 구조 변경
- 사용자가 실행 중 Chrome 창을 닫음
- 발행 버튼을 눌렀지만 성공 여부를 확인할 수 없음

실행 상태는 `run.json`과 `HISTORY.md`에 남습니다.

```text
방금 작업의 마지막 성공 단계와 실패 원인, 안전한 재개 위치를 보여줘.
```

성공이 확정된 원고는 재개할 때 건너뜁니다. 발행 여부가 불확실한 `uncertain` 항목은 자동 재시도하지 않습니다. 네이버 관리 화면에서 실제 발행 여부를 확인한 뒤 정확한 글 URL과 함께 알려야 중복 없이 상태를 확정할 수 있습니다.

사용자가 Chrome 창을 직접 닫아 중단한 경우 다음 순서로 복구합니다.

1. 네이버 관리 화면에서 해당 원고가 발행되지 않았는지 확인합니다.
2. `프로필 1,2 창 다시 열어줘`라고 요청합니다.
3. 로그인·글쓰기·템플릿 상태를 다시 확인합니다.
4. 같은 실행 폴더의 미완료 원고부터 재개합니다.

## 모바일 Remote 사용

모바일 Remote는 휴대폰에서 명령만 보내고 실제 Browser, Chrome 프로필과 파일은 연결된 Windows 또는 macOS 호스트에서 사용합니다. 호스트는 켜져 있고 온라인이어야 하며 Codex 데스크톱 앱이 실행 중이어야 합니다. Computer Use가 필요한 동안 화면을 잠그지 말고, 업로드 중인 프로필 Chrome 창도 닫지 마십시오.

자세한 설정은 [모바일 Remote 사용 안내](docs/MOBILE_REMOTE.md)를 확인하십시오.

## 자주 쓰는 요청 모음

```text
등록된 네이버 프로필을 번호, 별칭, 블로그 URL, 글쓰기 URL과 함께 보여줘.
```

```text
프로필 3 생성해줘. 별칭은 여행 블로그고 URL은 https://blog.naver.com/example 이야.
```

```text
프로필 1,2,3 Chrome 창을 각각 열어두고 로그인·글쓰기 접근을 확인해줘.
```

```text
"서울 맛집" 블로그탭에서 원고 3개 만들고 프로필 1,2,3에 임시저장해줘.
```

```text
이 내 글 URL을 내려받아 새 글 2개로 재생성하고 프로필 1,2에 바로 발행해줘.
```

```text
중단된 작업의 히스토리를 확인하고 성공하지 않은 원고부터 재개해줘.
```

## 문제 발생 시 먼저 확인할 것

1. 대상 프로필 창이 열려 있는가
2. 올바른 네이버 계정으로 로그인했는가
3. 등록 블로그 URL과 로그인 계정이 일치하는가
4. 각 계정에 `제목을입력해주세요1:` 내 템플릿이 있는가
5. 템플릿 안에 `제목을입력해주세요1`과 `본문2:`가 있는가
6. 다른 프로그램이 같은 `naver_N` 폴더를 열고 있지 않은가
7. CAPTCHA·접근 제한·작성 중 글 팝업이 표시됐는가
8. `run.json`의 상태가 `failed`, `uncertain`, `completed` 중 무엇인가

상세 복구 절차는 [문제 해결](docs/TROUBLESHOOTING.md)을 참고하십시오.

## 안전 및 서비스 정책

- 수집한 공개 글은 검색 의도와 공통 사실을 파악하는 자료로만 사용하고 문장을 복제하지 않습니다.
- 사용자가 제공하지 않은 방문·구매·사용 경험을 사실처럼 만들지 않습니다.
- 가격·영업시간·정책처럼 바뀔 수 있는 정보는 가능한 경우 공식 출처로 확인합니다.
- 로그인 제한, CAPTCHA와 접근 차단을 우회하지 않습니다.
- `발행`, `바로발행`, `자동발행`은 실제 공개 발행 승인입니다.
- 저장소에 라이선스 파일이 추가되기 전까지 재배포 조건은 저장소 소유자에게 확인해야 합니다.
- 네이버와 원문 제공자의 이용약관, 저작권과 관련 법규를 준수해야 합니다.
