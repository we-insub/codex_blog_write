# Mato Blog Codex

Mato Blog Codex는 네이버 검색 결과를 분석하고, Codex가 원고를 만든 뒤 등록된 로컬 Chrome 프로필로 네이버 블로그에 임시저장하거나 발행하도록 돕는 **Codex 플러그인**입니다.

이 프로젝트는 사용자가 Python 명령을 직접 조작하는 독립 실행 프로그램이 아닙니다. 설치 후 Codex 대화창에 평소 말하듯 요청하는 것이 기본 사용법입니다. PC 앞에서는 Codex 데스크톱 앱을 사용하고, 밖에서는 같은 PC에 연결된 ChatGPT 모바일의 Remote에서 동일하게 요청할 수 있습니다.

이 저장소에는 공유 가능한 스킬과 실행 스크립트만 들어갑니다. 네이버 로그인 세션, 계정 정보, 검색어, 생성 원고와 실행 히스토리는 각 PC에만 저장되며 GitHub에 포함되지 않습니다.

## 가장 빠른 사용법

Codex 대화창 또는 연결된 모바일 Remote에서 다음 한 줄을 입력합니다.

```text
"서울 맛집" 1번 프로필, 블로그탭
```

아무 옵션도 더 적지 않으면 다음과 같이 처리합니다.

1. 호스트 PC의 `@Browser`가 네이버 블로그탭에서 공개 글을 노출 순서대로 최대 5개 확인합니다.
2. Codex가 공통 검색 의도와 핵심 정보를 분석해 원고 **1개**를 만듭니다.
3. 로컬 Playwright 프로필 `naver_1`로 네이버 글쓰기 화면을 열어 **임시저장**합니다.
4. 입력한 명령과 검색·생성·업로드 결과를 로컬 `HISTORY.md`에 기록합니다.

기본값은 `1개 + 임시저장`입니다. 다음처럼 개수를 명시하면 정확히 그 수만큼 생성합니다.

```text
"서울 맛집" 1번 프로필, 블로그탭, 10개
```

`발행`, `바로발행`, `자동발행`처럼 공개 발행 의도가 명시되면 해당 요청 안에서 검증과 발행까지 완료합니다. 실행 ID와 배정 서명은 내부에서 다시 검증하지만, 사용자에게 같은 승인을 반복하거나 실행 ID를 다시 입력하게 하지 않습니다.

## v0.1 기능

- `@Browser`를 통한 네이버 `블로그탭` 또는 `통합검색` 공개 글 최대 5개 조사
- 중복 링크 제거 및 네이버 `PostView` 주소 정규화
- 검색 의도와 공통 주제를 바탕으로 Codex가 요청한 수만큼 원고 생성
- 플러그인의 `공통` 프롬프트를 PC별 편집 파일로 관리하고 생성할 때 그 수정본을 사용
- 기존 Mato `_함축.txt` 형식 검증
- 여러 네이버 프로필에 원고를 라운드로빈 배정
- 임시저장 또는 자동발행 전 대상과 배정표 확인
- 실행별 `HISTORY.md`와 기계 판독용 `run.json` 기록
- 중단된 실행의 상태 확인 및 완료되지 않은 업로드 재개

플러그인에 포함된 네이버 URL 다운로드 모듈은 글 본문 컨테이너에 있는 이미지를 크기로 제외하지 않고 순서대로 모두 `image_N.jpg`로 저장한 뒤, 실제 제목·`인트로1:`·`본문2:`·`ㅂㅂㅂ` 소제목·표 마커·이미지 위치를 보존한 `<제목>_원본_함축.txt`를 만듭니다. 따라서 이 기능만을 위해 Mato Helper나 `google-blog-auto` 소스를 설치·공유할 필요가 없습니다. 이미지 해시 변경, 허위 EXIF·메타데이터 생성, CAPTCHA·로그인 제한·접근 차단 우회는 포함하지 않습니다.

원고 프롬프트는 `~/.googleblog/mato-blog-codex/prompts/공통.txt`에서 직접 수정할 수 있습니다. 자세한 초기화·상태 확인·원본 동기화 명령은 [COMMANDS.md](docs/COMMANDS.md#mato-helper-공통-프롬프트-관리)를 참고하십시오.

## 요구 사항

- Windows 10 또는 Windows 11
- Google Chrome
- Git
- 최신 ChatGPT/Codex 데스크톱 앱
- 호스트에 설치된 **Browser 플러그인**과 활성화된 Computer Use
- Python 3.10 이상을 실행할 수 있는 `py` 런처

모바일 사용은 선택 사항이며 최신 ChatGPT iOS/Android 앱과 Remote 연결이 필요합니다. Codex CLI만으로는 `@Browser`와 모바일 Remote를 사용하는 기본 워크플로를 대신할 수 없습니다.

네이버 로그인은 자동으로 비밀번호를 입력하지 않습니다. 프로필을 처음 만들거나 세션이 만료되면 표시되는 Chrome 창에서 사용자가 직접 로그인해야 합니다.

## 설치

저장소를 복제하고 저장소 루트로 이동합니다.

```powershell
git clone <저장소-URL> mato-blog-codex
cd mato-blog-codex
```

이 저장소를 Codex 로컬 마켓플레이스로 등록하고 플러그인을 설치합니다.

```powershell
codex plugin marketplace add "$PWD"
codex plugin add mato-blog-codex@personal
```

마켓플레이스 이름은 [`.agents/plugins/marketplace.json`](.agents/plugins/marketplace.json)의 `name` 값입니다. 해당 값이 변경된 저장소에서는 `@personal` 대신 그 이름을 사용합니다.

데스크톱 앱의 Plugins Directory에서 **Browser**를 설치하고 Computer Use를 활성화합니다. 설치가 끝나면 Codex를 다시 시작해 스킬을 불러온 뒤 다음과 같이 요청합니다.

```text
Mato Blog Codex 초기 설정하고 기존 네이버 프로필을 찾아줘.
```

Codex가 내부 부트스트랩 스크립트로 이 PC에서만 사용하는 Python 가상환경과 Playwright 관련 의존성을 준비합니다. Python 스크립트를 직접 실행하는 방법은 일반 사용법이 아니라 [개발자·내부 문제 해결 명령](docs/COMMANDS.md)입니다.

## 요청 값과 추가 예시

Codex 대화창에서 다음과 같이 요청할 수 있습니다.

```text
기존 네이버 프로필을 찾아서 목록으로 보여줘.
```

```text
"서울 맛집" 1,2,3번 프로필, 블로그탭, 10개
```

자연어 요청에서 Codex가 확인하는 값은 다음과 같습니다.

| 항목 | 예시 | 설명 |
| --- | --- | --- |
| 검색어 | `서울 맛집` | 네이버에 입력할 검색어 |
| 검색 영역 | `블로그탭` | `블로그탭` 또는 `통합검색` |
| 버전 수 | `10` | 생략하면 10개, 명시하면 해당 수만큼 생성 |
| 프로필 | `1,2,3` | 업로드에 사용할 로컬 프로필 번호 |
| 방식 | `임시저장` | 생략하면 임시저장, 공개 발행은 `발행`·`바로발행`·`자동발행`처럼 명시 |

프로필을 생략하면 원고 파일까지만 만들고 업로드하지 않습니다. 공개 발행을 명시한 요청은 대상·검증 파일·실행 서명이 일치하면 중간 재확인 없이 발행까지 진행합니다.

## 일반 사용은 자연어로

설치가 끝난 뒤에는 Python 명령을 기억할 필요가 없습니다.

```text
등록된 네이버 프로필 목록을 번호, 별칭, 블로그 URL과 함께 보여줘.
```

```text
"제주 렌터카" 통합검색, 3개 만들어줘. 아직 업로드하지 마.
```

```text
방금 만든 원고를 2,4번 프로필에 배정하고 임시저장해줘.
```

```text
중단된 작업의 히스토리를 보여주고, 완료되지 않은 임시저장부터 재개해줘.
```

Codex가 내부적으로 실행하는 스크립트와 진단 명령은 [COMMANDS.md](docs/COMMANDS.md)에 분리해 두었습니다.

## Browser와 업로드 프로필은 서로 다릅니다

- 공개 검색과 자료 확인은 `@Browser`를 사용합니다.
- 네이버 로그인·글쓰기·임시저장·발행은 로컬 Playwright 프로필 `naver_N`을 사용합니다.
- Codex 내장 Browser와 cloud 브라우저 프로필은 PC의 일반 Chrome 및 `naver_N` 로그인 세션과 분리되어 있습니다.
- 따라서 `@Browser`에 로그인했다고 해서 `naver_1`에 로그인되는 것이 아니며, 반대도 마찬가지입니다.

이 분리는 공개 자료 조사와 계정 쓰기 작업을 명확히 나눕니다. 네이버 계정 로그인은 로컬 프로필 확인 과정에서 표시되는 Chrome 창에서만 직접 진행합니다.

## 모바일 Remote

ChatGPT 모바일의 Remote는 휴대폰에서 명령을 보내지만, 실제 저장소·플러그인·Browser·로컬 파일·Playwright 프로필은 연결된 호스트 PC가 제공합니다. 호스트는 켜져 있고 네트워크에 연결되어 있으며 데스크톱 앱이 실행 중이어야 합니다. Windows에서 Computer Use가 필요한 동안에는 세션도 잠금 해제 상태여야 합니다.

설정과 주의사항은 [모바일 Remote 사용 안내](docs/MOBILE_REMOTE.md)를 확인하십시오.

## 로컬 데이터 위치

| 데이터 | 기본 위치 | GitHub 포함 여부 |
| --- | --- | --- |
| Chrome 프로필 | `~/.googleblog/browser_profiles/naver_N` | 포함 안 됨 |
| 프로필 목록 | `~/.googleblog/local_agent/naver_profiles.json` | 포함 안 됨 |
| 전체 실행 기록 | `~/.googleblog/mato-blog-codex/HISTORY.md` | 포함 안 됨 |
| 실행별 자료 | `바탕화면/YYYY-MM-DD/<실행-ID>/` | 저장소 밖 로컬 폴더 |
| 플러그인 코드·문서 | 이 저장소 | 포함 |

집 PC 등 다른 컴퓨터에서는 저장소를 다시 설치하고, 그 PC에서 프로필을 별도로 생성하거나 발견해야 합니다. 로그인 세션과 계정 별칭은 Git으로 동기화되지 않습니다.

## 독립 실행

프로필 생성·로그인 유지·임시저장·이미지 삽입은 모두 이 플러그인 내부의 Playwright 코드로 실행합니다. `google-blog-auto` 또는 Mato Helper 설치본은 필요하지 않습니다. 기존 `~/.googleblog/naver_browser` 또는 `naver_browser_N` 폴더는 같은 번호의 프로필로 선택할 수 있으며, 브라우저 데이터를 다른 폴더로 복사하지 않습니다. 로그인 확인 중 필요한 세션 보강도 해당 `naver_N` 영구 프로필 안에서만 처리하며 인증값을 출력하거나 프로필 목록에 저장하지 않습니다.

- `프로필1 "서울맛집"`을 입력하면 `naver_1`, 통합검색, 원고 10개, 임시저장으로 해석합니다.
- 프로필 번호에는 고정된 최대 개수 제한이 없습니다. `naver_1`부터 필요한 만큼 `naver_N`으로 증가합니다.
- 먼저 플러그인 내장 세션 연결기로 프로필 1 로그인 유지 상태와 글쓰기 권한을 확인합니다.
- Codex 내장 Browser로 공개 검색 결과의 블로그 글을 최대 5개 분석하고 원고를 생성합니다.
- 검증된 `_함축.txt`를 플러그인 내장 업로더로 프로필 1 글쓰기 주소에 임시저장합니다.
- 비밀번호, 쿠키 값과 세션 값은 플러그인으로 복사하거나 출력하지 않습니다.

현재 프로필 연결만 확인하려면 Codex에 `프로필 1 로그인 확인해줘`라고 요청하면 됩니다. 전용 창을 계속 유지하려면 `프로필 1,2 창 열어둬`라고 요청할 수 있으며, 이후 업로드는 열린 창에 재연결합니다. 공개 발행은 자연어 요청에 `발행`, `바로발행`, `자동발행`처럼 의도가 명시된 경우 같은 작업에서 완료합니다.

## 본인 소유 이미지 정리

본인 소유 또는 사용 허가된 이미지는 URL 다운로드 직후 자동으로 방향을 보정하고 GPS·EXIF·XMP·ICC 데이터를 제거한 뒤 같은 파일명으로 정상 재저장합니다. 각 출처 폴더의 `image-processing.json`에는 파일명, 크기, 처리 전후 SHA-256과 메타데이터 존재 여부만 기록하며 원래 위치·카메라·설명 값은 기록하지 않습니다.

네이버와 관계없는 로컬 이미지도 Codex에 `이 폴더의 내 사진 메타데이터를 정리해줘`라고 요청하면 같은 모듈로 처리할 수 있습니다. 이 기능은 허위 촬영일·위치·카메라 정보를 만들거나 픽셀을 은닉 변조하지 않습니다.

내 글 URL의 사진을 새 원고마다 따로 쓰려면 다음처럼 요청합니다.

```text
내 글 URL의 이미지 다운로드 → 사진세탁 → 새 원고 3개 생성
```

이미지는 한 번만 다운로드합니다. 이후 원고가 3개면 각 원고 폴더에 독립된 이미지 데이터셋을 3개 만들고, 원본 데이터셋 1회 + 원고별 데이터셋 3회의 정리 작업을 실행합니다. 원고마다 `image_N.jpg`, 이미지 태그, `image-processing.json`이 따로 생성됩니다.

## 안전 및 사용 원칙

- 수집한 다른 블로그의 전체 원문은 분석 중 임시로만 다루고 영구 기록하지 않습니다.
- 원고는 공통 정보와 검색 의도를 새롭게 구성하며 문장을 복제하지 않습니다.
- 실제로 하지 않은 방문·구매·사용 경험을 사실처럼 만들지 않습니다.
- 시점에 따라 달라질 수 있는 가격, 영업시간, 정책 등은 가능한 경우 공식 출처로 다시 확인합니다.
- 로그인 만료, CAPTCHA, 접근 제한이 감지되면 우회하지 않고 중단합니다.
- `발행`, `바로발행`, `자동발행`은 실제 공개 발행입니다. 해당 표현이 요청에 있으면 대상과 검증 서명을 내부 확인한 뒤 중간 질문 없이 발행까지 진행합니다.

저장소에 라이선스 파일이 추가되기 전까지 재배포 조건은 저장소 소유자에게 확인해야 합니다. 이 도구를 사용할 때는 네이버 및 원문 제공자의 이용약관, 저작권과 관련 법규를 준수해야 합니다.
